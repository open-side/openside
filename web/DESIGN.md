# openside web design

The web app adopts the design system of [aside-relay](https://github.com/mym0404/aside-relay) (MIT): its tokens, layout metrics, controls and interaction patterns.

## Philosophy

- One conversation column floating on a soft gradient backdrop (`--backdrop`: mist blue → lavender → peach in light, deep slate → periwinkle → rose in dark). Content leads; chrome is frosted glass that stays out of the way.
- Quiet colour. Hierarchy comes from weight, size, spacing and soft surfaces over the gradient; the palette stays neutral and one primary colour marks the action and state that matter: send, the active choice, "Needs you".
- The phone layout is the reference. Desktop widens the canvas and pins the sidebar but changes nothing else.
- Every command lives where the object lives: a queued message has its own menu, a conversation row has its own menu, and a ticket carries its own buttons.
- Motion is short and only confirms what happened. Under reduced motion, overlays fade instead of moving.

Tokens are defined in `src/styles.css`. Primitives (`src/ui/ui.css`) and screens read only these variables.

| `--bubble` | `#f1f1f1` | `#181818` | user messages |
| `--text` | `#171717` | `#f3f3f3` | body text |

| `--glass` / `--glass-border` | white 60% / black 8% | ink-navy `rgb(24 28 46)` 70% / white 12% | frosted chrome: header pills, the three sidebar cards, event-chip lists. Blur is `--blur-glass` (50px, saturate 1.6), shadow `--shadow-glass` (`0 8px 40px`) |
| `--hover` | ink 8% | paper 8% | translucent hover wash on every control; never an opaque grey |

Strong glass stays dark in both themes. Inside it (`.bubble.assistant`, `.ticket`, `.panel`, `.composer`, `.composer-readonly`) `--text`, `--muted`, `--border`, `--surface`, `--canvas`, `--hover`, `--hl-*` and `--primary` are re-pointed at light-on-navy values, so Markdown, code, tables and buttons need no per-component rules; `--primary` there is the white pill and links use `--link`.

Motion uses `--fast: 140ms`, `--normal: 220ms` and `--ease: cubic-bezier(0.2, 0, 0, 1)`. Syntax colours are the `--hl-*` tokens.

## Typography

- UI and content use Wanted Sans Variable; code uses D2Coding. Both fonts are bundled under `src/assets/fonts`, and nothing loads from the network.
- Body text is 16px with a line height of 1.65. Code blocks are 0.8125rem.
- The header title is 1.0625rem at weight 650. Section headings are 600, and sidebar group labels are 0.75rem muted at weight 500.
- Brand: the mark (`BrandMark` in `src/ui`, drawn in `currentColor` so it follows `--text` in both themes) then the word "openside" at 1.3125rem, weight 650, letter spacing -0.5px. The app icon `public/icons/icon.svg` is the same mark in `#f4f3ee` on a `#111318` rounded tile; `icon-maskable-*.png` use a full-bleed tile with the mark inside the maskable safe zone. The wordmark for docs is `docs/assets/logo.svg` (`logo-dark.svg` for dark backgrounds): the mark plus "openside" set in Lexend (OFL-1.1) at weight 450, converted to paths.

## Layout

| Metric | Value |
| --- | --- |
| Header | 64px, no bar: a round menu button (drawer only), the title as a frosted pill (centred on phones), the actions pill; the transcript fades out underneath |
| Sidebar | 288px column inset 10px from the edges, pinned at ≥ 821px; a drawer below that. Three separate frosted cards 10px apart (brand, the people list, History/Workspace/Settings), so the gradient shows between them. In the drawer the cards sit on the gradient itself |
| Content column | 736px |
| Composer | 768px strong-glass pill (radius 28) floating on the gradient with no dock background; a text row over a bar of + (Add files), compact tool pills (none in the assistant's thread), then Stop/Send. Stopping one Task, with ✕ on its live card, asks "Stop this task?" (Keep running / Stop task) and leaves the agent and the other Tasks running |
| Phone sheet | dialogs become bottom sheets at ≤ 700px |

- Sidebar, from top to bottom: brand, then the people list: the assistant first, then teammates (pinned first, then the latest conversation first). There is no New chat and no search; each person is one continuous thread. Teammates hidden from the sidebar fold behind a muted "Hidden · N" disclosure, and retired ones live in History. History, Workspace and Settings sit at the bottom.
- Person rows are at least 56px tall with a radius of 16 (`--radius-row`): a 40px round avatar (initials on one of eight fixed accent colours, `components/avatarTone.ts`; three small dots in a pill on its corner while the person works), the name, and a muted second line (the live activity in a mixed accent while running, otherwise the last message, otherwise the role). On the right sit the time (time today, weekday this week, date before that) and either the "Needs you" badge or an accent unread dot. Unread is per device (`state/seen.ts`): the first roster a device sees counts as read, and the open thread never shows unread. The open row is an 11% ink wash. Every label truncates with an ellipsis and keeps its full text in `title`; nothing in the sidebar scrolls sideways (`crates/openside-e2e/tests/web_overflow.rs`).
- A person's thread (`/agents/:id`): the header pill holds a 32px avatar, the name and a subtitle (Needs you, the live activity, or the role), and opens the profile. An empty assistant thread shows the 64px avatar, "Hi, I'm <name>" and the starters above the composer, whose placeholder names the person. A retired teammate's thread is read only, with a Restore note in place of the composer.
- Profile sheet: a wide dialog (a bottom sheet on phones) with identity first (64px avatar preview, name, initials, colour swatches with a ring on the chosen one), then role, voice, responsibilities and boundaries, then Model, Permissions and reach, Skills and Routines and memory sections divided by hairlines. Save sends only what changed; Retire is a danger button at the end and opens the hand-over or pause choice.
- History (`/history`) uses the conversation row style for earlier conversations (search, Earlier/Archived tabs, the row menu) and person rows for retired teammates. Workspace → Team lists everyone as resource cards with their avatar.
- Ordinary conversation menus offer Delete conversation after a confirmation describing the irreversible removal and file deletion; success refreshes History and returns an open deleted thread there. Archive remains reversible. Agent home threads, including the chief's, offer neither Delete nor Clear. `docs/specs/app-help.md` is the static app capability contract supplied to the front; focused tests compare its route and menu names with the web UI. Conversation titles are preserved and no session model labels are added.
- The static capability map is ≤1.5KB and lives only in the front/chief instructions, never worker profile prompts. Broken-output reports are acknowledged without speculative rendering diagnoses; the front offers a real document attachment or native result card. Discovered sign-ins are not called verified connections, and authentication status never implies a grant to every agent.
- When the daemon cannot be reached, the shell shows one `.connection-banner` ("Can’t reach openside. Reconnecting…") instead of per-screen errors.
- Messages: assistant replies are strong-glass bubbles (radius 22, padding 14×18) that hug short text and cap at the column; user messages are lighter translucent bubbles on the right, at most 80%. No avatars.
- Scrolling: the transcript is the only scroller on the conversation route (the page, shell and header never scroll) and uses `overscroll-behavior: contain`. Inner scrollers opt into `.thin-scroll`: no scrollbar track ever; a thin pill thumb stays invisible until the reader scrolls (`data-scrolling`, set for 0.9s by `ui/scrollReveal.ts` after a wheel, touch, key or pointer input, never by the transcript pinning itself) or hovers, and touch devices keep their native overlay bar. In the transcript the track also stops short of the floating header and composer, and a reserved gutter keeps the column centred on the composer. The transcript follows a streaming turn only while the reader is at the bottom: the first upward move stops it (`pages/scrollFollow.ts`), coming back within 80px resumes it, and content that grows without an event (images, cards) keeps the end in view while following. Otherwise the jump-to-latest button shows and nothing moves under the reader. A new conversation always opens on its latest turn; scroll position is not restored on reload.
- Delivery: the person's newest message carries a small note under it, as a messenger does: "Sending…" until the daemon takes the POST, "Sent" once accepted (an idle session starts on it at once; a message sent during a run stays in the Queued list instead), "Read" once the agent has it (`message.injected`); "Read" stays under the newest message after the answer. When the agent starts on it, three dots bounce one after another (a slow fade under reduced motion, with `aria-label` "Agent is working") until the first text or tool row arrives. A POST that fails shows "Not sent · <reason>" with Retry (same `message_id`, so the daemon deduplicates) and Discard; a run that died after reading the message shows "Not finished", with Retry only when no error row follows. The state is derived from the event log (`message.queued` / `message.injected` / `turn.started`) plus this device's own in-flight sends (`state/outgoing.ts`), so a reload shows the same thing.
- Time: a centred muted line ("Today 14:05", "Yesterday 9:12", a weekday this week, a date before that; `components/timeStamp.ts`) goes before the first message and before any message that starts a new day or follows an hour's pause. No divider rules.
- The assistant's thread (front agent, `Timeline front`): the assistant only talks; its work runs in background Tasks. Each `send_message` arrives whole as one left bubble (nothing streams), and the three typing dots sit in a strong-glass bubble of their own while a turn is open (`turn.started` until `turn.ended`). No tool chips, no status line and no Task reports (`task-report-*` messages) appear in it. It stays minimal: no Files or Agents pills, no counts, ids or timestamps beyond the time separators; a document shows only when the assistant attaches it to a message.
- Attached documents (`components/MessageDocument.tsx`, `assistant.final.attachments`): Markdown documents sit at the top of the bubble of the message that carries them. `inline` ones render in place in a glass inset, clipped at about twelve lines with a fade and "Show more"/"Show less"; `panel` ones are a card with the title and three faded lines that opens beside the thread on desktop (a full-height right panel) or as a full sheet on a phone, with Copy and Close.
- Visual blocks (```` ```html visual ````/```` ```svg visual ````, `components/VisualFrame.tsx`): drawn as inert images (`components/visualImage.ts`), never frames: SVG as is, HTML laid out as XHTML in an SVG `<foreignObject>`, scripts and external loads stripped. They are transparent, take the page's text colour and the system font as defaults, fit the column (no inner scrollbars) and are as tall as what they paint (HTML is measured by drawing it once; content sized to the viewport gets a 16:10 page). A visual that cannot be drawn says so plainly, and Source shows its code either way.
- Tool calls (other threads): a finished run of calls folds into an event chip (`✓ Browsed example.com`, `Used 3 actions`, failures counted) that opens onto a glass list, one line per call (name, the file/URL/command in mono, a state only while running or after failing); each line opens the arguments and result. While a run has nothing new on screen, the last row is the status line: a muted outlined pill with shimmering text naming what the agent is doing ("Opening nid.naver.com", "Clicking on nid.naver.com", "Reading a page", "Thinking"; `components/toolStatus.ts`). It opens onto the same list and disappears when text streams or a card asks the person something. Task bookkeeping calls (`create_task`, `steer_task`, `cancel_task`, `get_tasks`, `get_models`, `send_message`) never show as chips.
- Live browser card (`components/BrowserPreview.tsx`), for an agent that browses itself: once a conversation has used the browser, a white card (radius 24, white in both themes because it is the agent's screen) sits at the top of the column, showing the agent tab's read-only screencast fitted at the top of a 4:3 box (capped at 40vh / 380px on wide screens). It sticks under the header while the agent works, while its done chip shows and as the slim pill; idle or waiting on the person it scrolls away with the transcript, so it never covers the card that asks. Frosted light pills sit over its bottom edge: the status pill (three circling dots and the same phrase as the status line while running; the tab title with a live dot when idle), "Action needed" with an amber triangle while a request waits (tapping it scrolls to the request), Minimize, and one control whose label says what it does: a labelled "Stop" pill while running, which asks first, and a Close × only when nothing is running, which hides the card until the agent uses the browser again. A `browser_pointer` click shows a white ripple at its point (`browser_act` targets refs and has no coordinates). After a run of at least a second, the status reads "✓ <first sentence of the reply>" and the card folds after 4s into a slim centred pill: a thumbnail, the status, Restore and ×. Tapping the picture or thumbnail opens the browser sheet. No tab open hides the card. The card's title is the tab's document title, never a heading read from the page.
- Tasks (`components/TaskUnit.tsx`): each Task is one small left bubble directly below the message that started it (a Task started before the turn's words goes after them). It shows only the current step with a state mark (circling dots, a triangle, a check or an alert): the daemon's short `status_text` ("Opened github.com/trending"; no tool names), "Waiting for you" (tapping it scrolls to the request), or the first sentence of the report once done; up to two earlier steps sit beneath it as faint hairline pills. No title, no state pill, no sheet, and no steering anywhere. Its own calls never enter the conversation; cards a Task raises for the person still appear in the thread, attributed to it.
- Task browser: a Task with a browser tab shows the tab instead. While it works, the newest such Task opens by itself into the live card, as wide as the column up to 560px: the live screencast when the session's stream is on that tab, otherwise that tab's last picture, otherwise a skeleton reading "Loading the browser"; never a blank page. Nothing sits over the top edge (no title, no Live label); the pills over the bottom edge are the status ("Action needed" scrolls to the request), Collapse, and ✕, which stops the Task after the "Stop this task?" confirmation and is hidden once the Task has left the page to write its answer. When the Task ends the card folds back to the step bubble with the result line; older Tasks stay folded, and the person's own open or close choice sticks.
- Radii (`--radius-*` in `styles.css`, measured from the reference; components never use raw px): 4 `xs` link washes, 8 `sm` inline code and tags, 12 `md` small controls, 16 `lg` rows, inputs, menu items and code blocks, 20 `xl` media tiles, 24 `2xl` every surface (bubbles, cards, tickets, composer, sidebar cards, menus, dialogs, `--radius-glass`/`--radius-card`/`--radius-float`), 9999 `pill` every button, chip, tab and segment; icon buttons stay circles (50%). Spinners follow the text colour; the accent is kept for focus and selection outside glass.

## Controls

- Icons come from Lucide at stroke 1.8 (`ICON_STROKE`). Icon buttons are 44px circles; ghost by default, outlined or glass where they float.
- Buttons come in primary, secondary, ghost and danger, with the pill radius (`--radius-pill`). Pressing scales them to 0.97 (icon buttons to 0.9).
- Floating surfaces (menus, dialogs and sheets, the phone drawer, toasts, select lists, the skill-mention list) all take one recipe: the `.glass-float` class (`ui/ui.css`) over the `--float-bg` / `--float-border` / `--float-shadow` / `--float-blur` tokens, with `--radius-float` (24, the 2xl step) for every float. New popovers add the class; they never copy a background or blur. Without `backdrop-filter` support the class falls back to `--float-bg-solid`; under `prefers-reduced-transparency` every glass token becomes opaque and unblurred (one media block in `styles.css`). Backdrop filters cannot nest, so the mention list and the login-card suggestions, which open inside a blurred card, stay opaque.
- Menus (`PopoverMenu`) are glass cards with a muted title, 40px items (44px under a finger) at radius 16 (menu radius 24 minus 8px padding), a quiet leading icon, and danger items in red. A highlighted row gets an 8% text tint, a pressed row 14%, a danger row a red tint, and keyboard focus adds a 2px accent ring; separators are 12% text hairlines.
- Select (`ui/Select.tsx`) replaces every native `<select>`: a trigger button plus a `.glass-float` listbox whose rows reuse the menu item styles. It supports icons or swatches per option, groups, disabled options, a check on the selected row, arrow/Home/End/type-ahead/Enter/Escape, and becomes a bottom sheet with 48px rows at ≤ 700px. `variant="field"` fills its container like an input; `variant="inline"` is a compact trigger for rows. Give it an `id` and point a `<label htmlFor>` at it. The extension side panel has the same control for its conversation picker (`extension/src/picker.ts`), and login cards get an editable suggestion list (`ui/suggest.ts`) instead of `<datalist>`; never use a native `<select>` or `<datalist>`, whose popups CSS cannot style.
  - Queued message: Edit message / Send now / Cancel message.
  - Conversation row: Pin / Rename / Archive.
- Dialogs (`Dialog`) are centered cards on wider screens. On phones they become bottom sheets with a grab handle; `back` adds a leading chevron, and `size="wide"` gives a wider card.
- Toasts sit at the top center as glass pills with a green or red status icon. They slide in, then fade out on dismissal.
- Segmented controls (`Segmented`) set the selected segment on a raised surface.
- Switches (`Switch`) are `role="switch"` checkboxes for on/off settings that apply immediately: a 36×22 track in a 44px hit box, the accent only when on.

## Conversation cards

Every question, approval, code, login, choice, payment, form, takeover, hire, handoff, activity row and presented result (products, places, tables, orders) is one **card**: a daemon-built `Card` (`Ticket.card`, `card.presented`, `tool.ended.card`, team events) of typed blocks and typed actions. One plain-DOM renderer, `src/cards/` (`render.ts` mounts it, `blocks.ts` draws blocks, `fields.ts` inputs, `actions.ts` dispatches actions, `copy.ts` owns the standard English labels, `cards.css` the look), is mounted by `components/ConversationCard.tsx` in the web app and imported as is by the extension side panel. There is no second form renderer, legacy ticket card, login form or code sheet; the timeline shows a card where it used to show a ticket row and the tool rows the card now represents.

- **Surface.** Strong glass in both themes (`--glass-strong-*`, `--radius-glass`), 424px wide (512px for result tables and lists), full width below 480px. Primary action is the white pill, secondary actions ghost. Targets are 44px; inputs are 16px on phones so the page never zooms.
- **Collapsed bubble.** A pending ask rests as a 48px pill: the site icon, a one-line safe summary (never a field value) and a chevron. It expands in place on click or Enter/Space, with a short size-and-fade morph (instant under reduced motion), moves focus to the first field and collapses on Escape or the close button. Collapsing is not rejecting; typed secrets are emptied. Fields are only built once the card is open. A settled card is a receipt pill with a status mark (done, failed, expired) and a polite live announcement; it holds no field and no action. Presented results (lists, tables, orders) are always open; long ones preview three rows behind "Show all N".
- **Icon and origin.** The site mark is the favicon the daemon normalized to a `data:image/png` URL, or the authenticated icon route for exactly the card's own origin; any other source falls back to the initial of the host. The verified-origin line (scheme, punycode host, non-default port; mono, wrapped, never ellipsised) is the daemon's, shown on login, code and payment cards; a page's own claimed name is never presented as identity. Images (products, places, tables, orders) load only from the session's `cards/media/*` artifacts through the authenticated artifact route and are raster only.
- **Fields.** Labels and `autocomplete` tokens for standard fields come from the client (`username`, `current-password`, `one-time-code`, `cc-number`, `cc-exp`, `cc-csc`), so a model never names them. Secret fields carry `data-feedback-redact`, never a `value` attribute and never an initial value. Passwords get an eye toggle; card number, expiry and CVC format as typed (expiry and CVC share one row); a field whose destination differs from the card's origin says so beside the field; text fields may offer saved suggestions. Enter in a field presses the primary action once.
- **Secrets are never echoed.** Values are read once, every field is emptied, and only then is the request awaited; a refusal, a settle elsewhere, Escape, collapse and dispose all leave the fields empty. The one restore is a 403 on saving login details (the person may lack approval rights): the details return, saving is refused in words, and nothing is sent again until the person presses the action. Chat text, receipts and the text fallback (`cardText`) show `[secure input]`, not values.
- **Code, authenticator.** A code card is one labelled one-time-code input (separators the site prints are dropped; emailed letters kept). When the daemon allows registering, a collapsed "Save this site's authenticator" section takes a masked setup key or `otpauth://` link: with "Save to vault" on it sends `{totp}`, off it computes one code locally and sends only that. A 403 keeps the form, says saving needs approval rights, and fills just this code from the key already pasted. It is hidden on a device without the approve scope.
- **Login, choice.** Login fields mirror the page; other sign-in options are labelled 48px provider buttons with locally drawn marks (`glyphs.ts`); saved accounts and page options are rows. A choice with an action runs it on click; plain options are radios with one primary action.
- **Result cards.** Lists show thumbnail, name, facts, price and rating; money and ratings are integers formatted client-side. Tables have real column headers, a focusable scroll region, right-aligned numbers and an optional per-row site mark. A total is pinned below the clipped body. Links open with `noopener,noreferrer` and only http(s). Notices are inline or a bubble beside the card and carry their tone as an attribute.
- **People.** Hire and handoff cards pair avatars (`avatar avatar--32 avatar--<tone>`; the daemon's colour is mapped to an allowlisted tone, never written into a style).
- **Where they appear.** In the conversation, in place; a pending ask is moved to the end of the thread so the newest thing on screen is the thing that needs the person. Off-thread attention requests (a code, a login, a choice, a phone approval or an authenticator offer) dock under the header (`components/CardAttention.tsx`): one `ConversationCard` plus a link to its conversation, with the dock's height reserved in the scroller. A tapped push (`?ticket=`) opens the full-screen `components/CardSheet.tsx`, which hosts the same card with `layout="sheet"` and closes when it settles. The extension panel lists pending requests of its tab's conversations and any attention request, open by default, and shows cards that arrive as `card.presented`; actions the panel cannot perform (remote screen, in-app navigation) are not offered.
- **Actions the host owns.** `ticket_resolve`, `ticket_reject`, `ticket_done` and `link` are handled by the card. `follow_up`, `open_thread`, `open_ticket`, `open_connection`, `team_command`, `takeover` and an edited `hire` go to the host (thread view, team actions, takeover view); a target nobody handles shows a plain error instead of doing nothing.

## Workspace

Workspace and Settings open as frosted glass sheets (`.ui-dialog`: `--glass` with `--blur-glass`, `--radius-glass`). Their sections (`src/pages`, styled in `pages.css`) share one list pattern built from `pages/blocks.tsx`:

- **Grouped lists.** Rows of a list sit in one glass inset (`--glass-inset-bg` / `--glass-inset-border`, radius 18) with hairline dividers, not as separate cards. Small tints (tags, icon tiles, code) mix `--text` over transparent so they work on any backdrop. A section header carries a muted summary (count, mode) on the left and at most one compact add button on the right.
- **Rows.** `ResourceCard`: title, one muted detail line, optional leading icon in a neutral tile. Row actions go in a trailing "…" `RowMenu` ("Options for <name>"), the same menu as conversation rows; destructive items are red and always confirm. On/off state is a trailing `Switch`, never a pair of Enable/Disable buttons. Expandable history uses `Disclosure`.
- **Badges carry state only:** neutral (read-only, kind), success (connected, unlocked, completed), attention (paused, rate limited, unavailable), danger (failed, denied, rejected). Never the accent colour.
- **Human text.** Schedules, run states, dates and policies are worded for people (`pages/format.ts`: "Weekdays at 08:00 · Asia/Seoul", "in 2 hours"); raw cron expressions and enum values only appear where a person types them.
- **Loading, errors and scope.** `ResourceView` shows a spinner, a load error with "Try again", or, on 403, `ScopeNotice` naming `openside pair --scope admin`; add buttons are hidden when the device lacks the scope.
- **Configuration** renders each schema key as a row: key and help on the left, control on the right (full width for text, lists and JSON). The save bar appears only while there are unsaved changes.
- **Operator screens** (`/agents`, `/sync`, `/policy`, `/diagnostics`, plus the Search model card on Memory) follow the same list pattern: sections with a muted lead, rows in a glass inset, one primary button per section. Anything that needs the daemon to restart shows `RestartNotice` (Restart daemon, confirm, reconnect when `boot_id` changes). Writes that need local authority show `LocalOnlyNotice` when refused. Progress (the model download) is a native `<progress>`, never an inline style. Secrets (sync passphrase and password) are read from the form at submit time and cleared from the inputs.
- **Connections** (`/connections`, next to Vault; `pages/ConnectionsPage.tsx`, `connections.css`) lists the sites the agent browser is signed in to, one `ResourceCard` per account. The leading tile is the site's favicon (a bounded `data:` URL, never fetched from the web; the site's initial otherwise). The title row is the site plus a state badge (Active, Sign in again, Expired, Not checked), the muted line is the masked account or "Account not identified yet", then a meta line (last use by whom, how it was signed in), an avatar stack with a coloured dot per agent (allowed, ask first, blocked) that opens the access dialog, and one visible button only when the sign-in needs attention ("Sign in again", or "Check now" for imported sites). "Sign in again" finishes silently when the Vault can, otherwise it leaves for the conversation's `?ticket=` sheet. The "…" menu holds Check now, Sign in again, Agent access, Activity, Add another account, and the red Sign out / Forget, each behind a confirmation; a card in a separate browser profile offers one "Remove account" instead, because removing it deletes the profile. Sites the cookie sweep found but nobody verified sit under a collapsed "Possibly signed in" disclosure. The Activity list below filters by connection, agent and action. The teammate profile sheet reuses `AgentConnections`: one access select per site, saved at once.
- **Phones:** every control in these sections is at least 44px tall at ≤ 700px, and nothing scrolls sideways at 390px.
- **Sign-in and pairing** (`TokenEntry`, `/pair`) are a strong glass card (`--glass-strong-*`) on the `--backdrop` gradient, with a pill input on `--glass-input-bg` and the white primary pill (`--pill-primary-*`), the same card language as the in-chat login cards.
- **Connect your phone** (`remote/ConnectPhone.tsx`; the first section of Remote access and the guide's phone step) is one glance: opening it has already issued a code through the best connection that is on (the daemon's preferred one), so the QR code (always black on white, `--radius-xl` tile) is the first thing on screen, then one status line ("Waiting for your phone…", "Connected as <name>", "This code expired."), the pairing link with Copy, and "Expires in m:ss" with a New code button. On a wide card the code sits left of its status; on phones it stacks and fits 390×844 without scrolling. "Through <connection>" with Change connection (only when more than one is on) and the collapsed "Phone name and permissions" are secondary controls under it, never a step before the code. While no connection can carry a code the same tile shows its state instead of a QR that would lead to a 404 ("The tunnel isn't reachable yet. Retrying…", the daemon's reason with Try again, or one button that turns on the default connection: Tailscale where installed, a saved relay, otherwise a Cloudflare quick tunnel).

## Models & accounts

`/models` opens as a wide dialog over the current screen, from Settings or the model picker's "Models & accounts" button (`models/ModelsPanel.tsx`; the first-run guide's Models step reuses it compact). Top to bottom: a warning callout while no model is ready, a Models block with two roles chosen once for the whole workspace and never per conversation or message: **Fast model** ("Answers quickly and hands bigger work to the reasoning model"; the first option is "Same as reasoning model", i.e. `fast_model` null) and **Reasoning model** ("Does the thinking for tasks and teammates"; the wire field stays `default_model`), each a select whose first group, "Recommended", holds the catalog models flagged `recommended_for` that role (labelled with their provider) followed by the remaining models grouped by provider, unavailable ones disabled and labelled; every option carries its tier (Fast, Reasoning, Frontier) as a small pill after the name and the curated strengths as a muted second line, and an id configured outside the current catalog says "Not in current catalog"; ordered fallback chips sit under the reasoning model. Every save sends both roles plus the fallbacks, so changing one never clears another. The first-run Models step stays compact and has no role pickers: the daemon pre-selects the recommended pair and Settings changes it later, then one section per provider from `GET /v1/settings/models` (Anthropic, OpenAI, Google). A provider holds any number of accounts, listed as `ResourceCard` rows: API keys (name, masked `••••` + last four; the value is typed in a password field in a dialog and never rendered after saving), Claude Code / Codex CLI subscription accounts (each with its own sign-in home; adding one ends in a dialog that shows the exact sign-in command and polls until it lands) and accounts configured elsewhere (broker, env), with status badge, one meter per usage window showing what is left of it ("18% left · resets in 2 hours"; the bar shrinks as it is used, and turns amber at 30% and red at 10% left; windows without a reading say "usage unknown"), an on/off switch and a Manage dialog (name, keep-in-reserve %, replace key, remove with confirmation). Under the accounts, a Rotation list is the ordered set of accounts that may serve the provider: reorder with the arrow buttons, remove, or add an account from the select; a new account joins on its own only when it is the provider's first, otherwise the add dialog offers it. Then the provider's models (four, "Show all" for the rest). A limited device keeps the same page with a note, no controls and no key metadata. The conversation menu's "Model account…" dialog (`models/SessionAccountDialog.tsx`) prefers one rotation account for the next messages. Credential sources close the page. Remove and key-replace copy says plainly that later requests stop using the account and that nothing is revoked with the provider.

## Channels

`/channels` opens as a wide dialog from Settings (`channels/ChannelsPanel.tsx`, `channels.css`). One `SectionList` per service (Telegram, Slack, Discord), each a grouped list of `ResourceCard` rows with its own "Add account"; an empty service says so in one line. A row is the service icon tile, the account name, a state badge (Connected, Off, Sign in again, Unavailable, Vault locked, Restart needed), the account id, then a line with the teammate that answers (24px avatar and name, from the team roster; "Will answer as … once it connects" while the account is not live). Slack and Discord rows carry the signed callback address (mono, wrapped) with a Copy button; when it points at this computer a note offers Remote access instead of pretending the platform can reach it. Accounts that still read config.toml say so and offer "Move to vault". Trailing: a `Switch`, Edit (Reconnect when the credentials were refused) and the "…" menu (Test connection, Edit account, Remove). Test results are one sentence from the client's `MESSAGES`, never upstream text. Remove confirms and names only that account. Devices without the admin scope see rows and a note but no controls; a pasted token's scopes are unknown, so the daemon decides and its refusal is shown. `RestartNotice` appears when an account needs the daemon to restart.

The account dialog (`AccountDialog.tsx`) holds name, id (new accounts only, derived from the name until edited), the teammate select with avatars, the allow-lists, the Discord application key, the Telegram poll timeout, credentials, the callback address and the on/off switch. Credentials are uncontrolled password inputs read with `FormData` at submit, emptied before the request, and never held in React state; an existing account never shows them and replaces them only through an explicit "Replace credentials". `options` replaces the whole object on the daemon, so the dialog sends the existing options with its edits, which keeps the file-only `api_base` and `listen`.

## First-run guide

`/welcome` (`src/onboarding`, styled in `onboarding.css`) is one centered strong-glass card (`.panel`, so the in-card token re-pointing applies and primary actions are the white pill) on the `--backdrop` gradient; the shell hides the conversation list while it is open (`.shell[data-focus]`). Width is 560px on desktop and the card fills the phone with 16px margins.

- **One card, six steps.** A 4px segmented progress bar (`aria-label` "Step 2 of 6: Agents"), the step's `h1` (focused on every step change, so screen readers announce it), one muted lead paragraph, the step body, then a footer: `Back` (ghost) on the left, one forward button on the right. The forward button is primary only once the step achieved something; otherwise it is the secondary "Skip this step", so skipping never looks like the recommended path. "Skip setup" is a ghost button in the header on every step but the last.
- **Rows reuse `ResourceCard` / `resource-list`.** The card re-points `--glass-inset-*` at their dark values, so agents, profiles and the vault read like Workspace rows. Profile choice is a radio list (`.onb-choice`), categories are checkboxes; badges say why something cannot be picked.
- **Preview before write.** `Import` stays disabled until a dry run of the same profile and categories has been shown; any change to either drops the preview. The result and preview use the same count list.
- **Colour carries state only:** success ticks in the recap and the paired-phone line, nothing else is tinted.

## Motion

- Sheets, drawers, backdrops, menus and toasts animate through CSS transitions keyed on Base UI's `data-starting-style` and `data-ending-style`. The jump-to-latest button scales in.
- A phone sheet closes when its handle is dragged more than 96px down or flicked faster than 700px/s, as in aside-relay. A shorter drag springs back. Only the handle starts a drag, so scrolling the content never closes the sheet.
- `prefers-reduced-motion: reduce`:
  - overlays keep a 120ms opacity fade without transforms;
  - press scale and the drag gesture turn off;
  - other transitions drop to 1ms;
  - scrolling to the latest message jumps instead of scrolling smoothly.

## Appearance

The Settings dialog (`components/AppearanceSettings.tsx`, styled in `pages/pages.css`) has the following rows. Every choice is stored in this browser only:

- **Theme mode:** System, Light or Dark.
- **Light theme / Dark theme:** `openside` (the tokens above) or one of the aside-relay palette presets in `src/theme-presets.ts`. A preset supplies canvas, text and accent; every other surface is derived from those with `color-mix`.
- **Primary color:** a colour picker plus preset swatches. A custom accent overrides the palette accent until you press "Theme default".

`public/theme-boot.js` applies the stored choices before first paint. CSP forbids inline scripts, so this file is static. It also keeps the `theme-color` meta tag in step with the canvas.

## Deviations from aside-relay

- **Motion:** CSS transitions instead of the `motion` library. Base UI already exposes enter and exit states, and the bundle stays smaller.
- **Fonts:** no web-font picker and no text-size setting, because the egress policy forbids runtime font downloads. Only the two bundled families are offered.
- **Date groups:** the sidebar groups only Pinned and Conversations, with no Today or Yesterday groups. The session API (`Session` in `docs/specs/openapi.json`) has no timestamps.
- **Default accent:** blue (`#2f6fed`) instead of aside-relay's purple. Swatches and presets cover the rest.
- **Text selection:** no global `user-select: none`. Agent output, code and tickets must stay copyable.
- **Markdown images:** shown as an alt-text pill, never as an `<img>`. All network traffic goes through `src/api` with the device token, and CSP limits `img-src`. An absolute http(s) image becomes a link the reader can open; relative and daemon URLs stay plain text. Attachments and files render through the authenticated artifact path instead.
- **Menus:** sign out lives in Settings. The sidebar bottom links to Workspace (skills, routines, memory, vault, devices, agents, sync, policy, diagnostics, configuration) and Settings, because openside has daemon management where aside-relay has its browser panel.

## Visual QA

`tools/qa/web-screens.sh [out-dir]` builds the app and runs `crates/openside-e2e/tests/web_screens.rs`. That test starts a hermetic daemon with seeded conversations, then captures every screen with headless Chromium at 390×844 and 1440×900, in light and dark (default `/tmp/openside-qa/redesign/core`). Seeded states include a short and a long thread, streaming with a subagent, a failed run, every ticket kind (options and free-text questions, secret, inline code request, takeover, device approval), long URL and Korean titles, archived and search results, and the daemon going offline. Set `OPENSIDE_SCREENS_ONLY=<screen,…>` to capture a subset, and compare the results with aside-relay's `docs/screenshots`.

The visual contracts also have automated acceptance tests, not just screenshots:

- `crates/openside-e2e/tests/web_glass.rs::web_and_extension_share_glass_styles_and_transient_status_pills` reads computed styles in the daemon-served web/PWA shell and the loaded MV3 extension panel at 390×844 and 1440×900, light and dark. It checks gradient backdrops, blurred header chrome and composer, strong-glass assistant and all five ticket surfaces, white primary pills, and status pills appearing and disappearing. Captures go to `/tmp/openside-qa/polish/LastRows/after` by default (`OPENSIDE_GLASS_DIR` overrides it).
- `crates/openside-e2e/tests/web_overflow.rs::every_route_and_surface_fits_all_supported_widths` checks 320, 360, 390, 768, 1024, 1280 and 1440px. It covers the conversation with login, choice, OTP, phone approval and confirm cards; expanded Tasks, tool activity and browser card; new chat; the collapsed and expanded code-request dock; Settings and every Workspace section; Pair entry; all six `/welcome` steps; and the phone/tablet conversation drawer and search. It checks document width and every rendered element's viewport bounds. Descendants of intentional inner scrollers are exempt, never their outer boxes; closed disclosures are not rendered. Set `OPENSIDE_OVERFLOW_DIR` to capture expanded activity at the two reference viewports in both themes.

Build `web/dist` first, then run `cargo test -j 4 -p openside-e2e --test web_glass --test web_overflow -- --test-threads=2` (through the local heavy-run wrapper where required). These tests require Chromium and the real sidecar Python environment; missing prerequisites fail rather than reporting an unexercised pass. Fixtures and pairing tokens are disposable; there are no live model calls.
