# 02. 사용자 문제 → openside 요구사항

에이전트 브라우저를 쓸 때 겪는 문제와 openside의 해결 방안을 정리했다. 해결책은 문제 원인이 아니라 증상을 해소하는 방향으로 서술했다.
모든 항목은 AC(수용 기준)로 검증한다. 단계는 `docs/05-roadmap.md` 의 마일스톤.

## 구조/플랫폼
| ID | 문제 | openside 해결 | AC | 단계 |
| --- | --- | --- | --- | --- |
| PP-1 | Linux를 1급 지원 플랫폼으로 다루지 않는다 | Linux 1순위 타깃. 플랫폼 의존 코드(Vault 잠금, 샌드박스, 창 포커스 검증)는 trait 뒤로 격리 | CI 에서 Linux x86_64 빌드·테스트 상시 통과, macOS/Windows 는 컴파일 체크 | M0~ |
| PP-2 | 브라우저 본체와 패치 코드가 오픈소스가 아니다 | 전부 오픈소스(MIT/Apache-2.0 중 택일, ADR-009). Chromium 패치는 패치 시리즈로 공개 | 라이선스·NOTICE 자동 점검(cargo-deny, 확장 의존성 점검) | M0 |
| PP-3 | 데스크톱 브라우저에 종속되어 있어 서버나 클라우드에서 실행할 수 없다 | 데몬은 헤드리스로 동작 가능. 관리형 브라우저 프로필(전용 user-data-dir)을 데몬이 기동·감시. 데스크톱/서버 동일 코드 | 디스플레이 없는 서버에서 Xvfb/headless 로 태스크 완주 E2E | M1 |
| PP-4 | 스마트폰에서 쓰려면 데스크톱 컴퓨터를 계속 켜 두어야 한다 | 데몬이 systemd user service 로 상주, 절전 inhibit(`systemd-inhibit`) 옵션, 서버 이전 가능 | 재부팅 후 자동 복구, 중단된 세션 resume | M4 |

## 개발자 표면
| ID | 문제 | openside 해결 | AC | 단계 |
| --- | --- | --- | --- | --- |
| PP-5 | TTY가 없으면 CLI가 아무것도 출력하지 않는다 | CLI 는 TTY 가 필수가 아님. 데몬 API 클라이언트일 뿐이고 `--json` 모드 제공 | `openside "x" \| cat` 가 JSONL 출력 | M1 |
| PP-6 | stdout 출력이 불안정해 외부 연동 시 디스크의 로그 파일을 직접 파싱해야 한다 | 구조화 이벤트 로그가 단일 진실원천. 형식은 JSON Schema 로 공개, 버전 필드 포함 | 로그 재생(replay)만으로 UI 상태 복원되는 테스트 | M1 |
| PP-7 | 이벤트를 받으려면 숨겨진 디버그 플래그에 의존해야 한다 | 공개 이벤트 스트림: SSE + WebSocket, `Last-Event-ID` 로 재개 | 연결 끊김 후 재개 시 누락·중복 0 | M1 |
| PP-8 | 내부 RPC나 데이터베이스를 직접 읽는 구조라 업데이트 시 연동이 깨진다 | 버전된 공개 API(OpenAPI 3.1) + 호환성 정책(deprecation 2 릴리스). omp 와는 문서화된 RPC wire schema 로만 통신 | 스키마 diff CI(호환 깨짐 감지), omp 업그레이드 시 wire 계약 테스트 | M1 |
| PP-9 | 메시지를 보낼 때마다 새 CLI 프로세스를 띄워 약 2초씩 걸린다 | 데몬이 세션별 `omp --mode rpc` 프로세스를 상주(warm). 프롬프트는 이미 열린 stdin 으로 전달 | 두 번째 메시지부터 첫 토큰 지연에 프로세스 기동이 포함되지 않음(계측) | M1 |
| PP-10 | 작업 중인 세션에 프롬프트를 보내면 아무 알림 없이 무시된다 | 데몬의 영속 큐. 모든 메시지는 id 를 받고 상태(queued/injected/dropped-with-reason)를 가진다. **조용한 폐기 금지** | 퍼징으로 임의 시점에 메시지를 쏴도 손실 0, 모든 메시지 최종 상태 관측 가능 | M1 |
| PP-11 | 질문 대기 상태에 걸린 세션을 원격에서 다시 진행시킬 수 없다 | 질문/승인은 API 객체(`/sessions/{id}/prompts/{pid}`). 어떤 클라이언트든 응답 가능, 만료·재전달 지원. omp 의 extension UI sub-protocol 로 수신해 객체화 | 데스크톱 UI 가 없어도 질문에 응답해 재개 | M2 |
| PP-12 | 승인 절차가 프롬프트 관례에 불과해 강제할 방법이 없다 | 승인은 `beforeToolCall` 훅/호스트 도구 레벨에서 **코드로 강제**. 모델이 거부 지시를 무시해도 실행되지 않음 | 위반 시도 레드팀 테스트 (프롬프트 인젝션 페이지로 결제 유도 → 차단) | M2 |
| PP-13 | 설정, 권한, OAuth 인증 절차를 원격에서 처리할 수 없다 | 모든 설정은 API 로 노출. OAuth 콜백은 `redirect_uri` 를 데몬/로컬 포트로 처리하고 원격 완료 플로우(`device code` 등) 지원 | 설정 화면의 모든 항목이 API 로 읽기/쓰기 가능(스키마 기반 자동 점검) | M4 |
| PP-14 | 원격 클라이언트에서 이미지, 음성, MCP를 지원하지 않는다 | API 메시지 모델이 이미지/오디오/파일 첨부와 MCP 서버 설정을 1급으로 가짐 | 첨부 이미지가 모델 입력과 transcript 에 모두 반영 | M3 |

| PP-17 | 문서와 실제 제품(수치, 옵션, 명령어)이 서로 맞지 않는다 | 문서의 수치·옵션·명령은 코드/스키마에서 **생성**(CLI help, API 레퍼런스, 설정 키 표) | 문서 빌드가 스키마와 불일치하면 CI 실패 | M1~ |
| PP-18 | 모델 사용량이 단일 계정의 쿼터에 묶여 제한된다 | **omp auth broker 멀티 계정**: 여러 구독/키를 풀로 등록, 사용량·reserve·priority 로 자동 로테이션(`auth.accountPolicies`), 세션/에이전트별 계정 풀. openside 는 계정 상태 표시·정책 편집 UI 제공 (→ docs/04) | broker 계정 N개 등록 시 한 계정이 rate-limit 되면 세션이 다른 계정으로 이동(핀 규칙은 omp 계약 따름) 하는 E2E | M1 |

| ID | 문제 | openside 해결 | AC | 단계 |

| PP-19 | 서드파티 비밀번호 관리자 확장 프로그램이 브라우저를 Chromium으로 인식하지 못한다 | 표준 Chromium UA/브랜딩 유지, `NativeMessagingHosts` 표준 경로 지원, 필요 시 doctor 가 호스트 파일 자동 연결 | 1Password·Bitwarden 확장 동작 E2E | M5 |
| PP-20 | 샌드박스 환경의 코딩 에이전트 안에서 CLI를 실행하면 설치 키(Windows)를 읽지 못한다 | CLI↔데몬은 유닉스 소켓/로컬 loopback + 토큰/소켓 권한 기반 인증. 사용자 계정 키링 의존 없음. 샌드박스용 스코프 토큰 발급(`openside token --scope browse`) | 샌드박스(다른 uid/네임스페이스)에서 스코프 토큰으로 호출 성공, 스코프 밖은 거부 | M2 |
| PP-21 | DRM(Widevine) 컴포넌트를 수동으로 업데이트해야 한다 | Widevine CDM 은 라이선스 제약. 지원 범위를 문서화하고 시스템 Chrome 의 CDM 을 사용하는 경로를 제공, 에이전트 작업 대상에서 DRM 재생은 비목표 | 문서화 + doctor 점검 | M5 |
| PP-22 | 대기 중인 승인이나 질문에 답하려면 데스크톱 앱을 직접 열어야 한다 | 푸시 알림+모바일 승인 카드, 채널 알림, 만료 시 안전 기본값(거부) | 폰에서 승인 → 태스크 재개 E2E | M4 |
| PP-23 | 비정상 종료, CPU 점유율 급증, 프로필 전환 버그가 발생한다 | 데몬/브라우저 컨트롤러는 Rust, 상태 기계는 이벤트 소싱+속성 기반 테스트. 크래시 덤프 로컬 수집(전송 안 함), 브라우저 프로세스 감시·재시작 | 장시간 소크 테스트(24h) 크래시 0, 브라우저 강제 종료 후 세션 자동 복구 | M1~M6 |
| PP-24 | 서브에이전트, steer, 메시지 큐 관련 버그가 발생한다 | 세션 상태 기계를 `openside-core` 에 순수 함수로 구현하고 모든 전이를 속성 테스트. 자식 승인은 부모로 라우팅, fork 는 완료 컨텍스트만 | 퍼징(proptest) 으로 불변식 위반 0: ① 메시지 중복/유실 없음 ② 자식 대기 교착 없음 ③ fork 에 미완료 tool-call 없음 | M1, M3 |

## omp 선택에서 오는 추가 단점과 대응
| ID | 위험 | 대응 |
| --- | --- | --- |
| OP-1 | omp 는 TypeScript+Bun 런타임 (Rust 단일 바이너리가 아님) | `AgentRuntime` trait 뒤에 두고, 설치 시 omp 버전 고정/검증. 장기적으로 Rust 네이티브 런타임을 같은 trait 구현으로 추가 가능 (ADR-002) |
| OP-2 | omp 업그레이드가 wire 를 깨뜨릴 수 있음 | omp 가 공개하는 `rpc-wire.schema.json` 에서 타입 생성 + 계약 테스트. 지원 버전 범위 명시 |
| OP-3 | omp 는 코딩 에이전트 중심 기본값 (코드 편집 등) | `browser-agent` 프로필로 도구/프롬프트 축소 (A-1, A-2) |
| OP-4 | 브로커 토큰 유출 시 모든 계정 노출 | openside 는 브로커 토큰을 로그·API·UI 에 절대 출력하지 않음. 토큰은 omp 가 읽는 파일 경로만 사용 |
